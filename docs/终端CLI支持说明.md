# 当前开发版终端接入

Electron 已接通自动捕获原终端身份、点击定位和手动查看确认。终端矩阵、VSIX/Lua 配置、进程失效规则、Wayland/SSH/WSL 限制见 [终端接入说明](../desktop/integrations/README.md)。

捕获绑定不激活窗口；点击完成/失败通知先确认，再定位原终端；手动查看必须核对前台窗口、对应标签页/分屏和同一完成轮次。500 ms 查看循环独立于日志更新。不能用“应用在前台”“目录相同”“CLI 进程存在”代替原任务已查看。

# 终端 CLI 支持范围

适用版本：v1.4.1。这里的“CLI”指在终端内运行的 Codex CLI、Claude Code、Grok、pi 等编码工具，不是 AllPet 自己的 `status/watch` 命令。

## 预期体验与当前能力

用户期望的完整流程是：在任意终端中运行编码工具 → AllPet 显示运行/等待/完成气泡 → 点击回到原窗口、原标签页、原任务 → 手动切回该完成任务后自动消泡。当前只完成其中部分能力。

| 能力 | macOS Electron 安装包 | Windows/Linux Electron 安装包 | macOS 源码 AppKit GUI |
| --- | --- | --- | --- |
| 读取支持格式的本地 CLI 日志并显示状态 | 支持 | 支持 | 支持 |
| 点击完成/失败气泡确认并保存 | 支持；定位失败也不恢复通知 | 相同 | 相同 |
| 点击运行中气泡 | 尝试定位，缺能力时提示；保留通知 | 相同 | 尝试验证并聚焦原终端 |
| 精确返回原终端标签页 | 尚未接通完整终端聚焦链路，包括 Codex CLI | 未实现 Windows Terminal/CMD/PowerShell/Linux 终端的精确任务定位 | 可验证进程、会话与 TTY 时尝试 Terminal/iTerm |
| 手动切回完成任务自动确认 | 原生桥接需有效原 TTY/绑定；默认日志未必提供，不是开箱即用保证 | 尚未实现 | 原任务绑定有效且前台选中 TTY 一致时可识别 |
| VS Code/Cursor 内置终端、tmux/screen 分屏 | 未实现精确 pane/任务定位 | 未实现 | 不能把 Terminal/iTerm 的 TTY 支持推广到这些环境 |

Codex Desktop 的深链和未读→已读回执仅适用于来源明确的桌面任务，不能套用到 Codex CLI。Codex 默认日志解析没有建立完整进程/TTY 绑定，因此当前 Electron 版不能承诺手动切到任意 Codex CLI 标签页后在 2 秒内消泡。终态通知仍可通过点击卡片或 × 确认。

## 日志读取条件

| 工具 | 默认本地来源 |
| --- | --- |
| Codex CLI | `~/.codex/sessions/` |
| Claude Code | `~/.claude/projects/` |
| Grok | `~/.grok/logs/unified.jsonl`、`~/.grok/active_sessions.json` |
| pi coding agent | `~/.pi/agent/sessions/` |

在同一台机器、同一用户的数据目录中运行受支持工具，AllPet 才能读取这些文件；非默认目录可修改 `platforms.<key>.paths` 后重启。只扫描兼容日志，不抓取终端画面。明确的内部子代理与符合现有过滤条件的记录不会显示。

SSH、容器、WSL、远程开发环境的数据不会自动同步到宿主机；即使手工配置了可读日志，也不代表已建立原终端定位关系。终端应用叫什么、是否有标签页或分屏，与任务监控是不同层面。

## 后续补齐的验收标准

需要按操作系统及终端逐一验证：创建可持久校验的会话→进程→窗口/tab/pane 绑定；点击只聚焦绑定目标；用户手动选中该目标且完成轮次一致时确认；终端关闭、PID/TTY 复用、分屏选错、任务新一轮、权限不足均不能误清除其他通知。完整支持前，不把新建终端或启动一份新 CLI 当作“返回原任务”。

这些是待实现/待验收范围，v1.4.1 仅修复 Windows/Linux 菜单，未新增终端聚焦实现。
