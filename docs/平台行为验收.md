## 操作后的具体表现

- 点击 done / failed 卡片：先移除该通知并保存确认状态，再尝试定位；定位失败仍保持已确认。下一轮真实任务可重新出现。
- 点击 running / thinking / waiting 卡片：尝试返回任务，不确认通知。
- 手动进入任务：只有精确识别到对应完成轮次才清除。仅打开某个平台、侧边栏出现同名任务、选中另一个任务都不能清除该平台其他通知。
- 检测中任务开始新一轮：旧回调不得清除新一轮。Codex 回执不能清除其他平台相同 sessionID 的卡片。
- 隐藏平台：不参加手动查看清理；保留历史及正常 TTL。菜单勾选平台和全部显示/隐藏保持菜单展开；Esc / 点击外部关闭。
- 读取超时、权限拒绝、缺少 TTY、绑定失效、焦点不确定：保留气泡，可由点击或 × 确认。
- 平台检测各自独立，每 500 ms 调度；浏览器慢请求不阻塞 Codex。500 ms 是调度间隔，不是无条件 2 秒清除保证。

## macOS 授权诊断与复现

安装包中 AllPet 的代码签名与辅助功能授权需要匹配。系统设置的旧条目可能对应此前构建；必要时由用户移除旧项，添加当前安装位置的 AllPet 并开启。应用不会自行授予权限或编辑系统授权数据库。

在 `~/.config/all-pet/manual-view-status.json` 同时检查新鲜的 `updatedAt`、`bridgeReady`、`hostAccessibilityTrusted` 与 `accessibilityTrusted`。该文件在桥接启动和存在完成候选时更新，旧 false 不代表重新授权后的状态。

本轮本地常驻应用已经确认主进程与原生桥接均授权成功；当时没有完成候选，所以没有测得真实手动导航的清除时延。不要把桥接应答时间或隔离回执测试时间当作真实导航验收。

真实验收步骤：产生完成气泡 → 在原应用手动进入对应任务 → 测量是否在 2 秒内清除 → 核对其他任务保留 → 重启检查已确认任务不恢复。随后测试同名任务、新轮次、缺权限及隐藏平台。尚未完成这些实测的平台必须保留上表的限制标记。
