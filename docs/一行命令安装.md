# 一行命令安装 AllPet

已经装有 **Node.js 22 或更新版本（含 npm/npx）与 Git** 的用户，在终端运行：

```bash
npx --yes github:haverainlilili/all-pet
```

macOS Terminal/iTerm2、Windows PowerShell/CMD、Linux 终端使用同一行命令。Windows 的 WSL 内请改到 Windows 终端执行，避免安装到 Linux 子系统。无需 Swift、无需 `-g`，也不用登录 npm 或 GitHub。没有 Node.js/Git 时，直接使用 [正式安装包](https://github.com/haverainlilili/all-pet/releases/latest) 更方便。

`npx skills add … -g` 用于安装 AI 技能；这里安装的是桌面应用。仓库根目录提供独立的 `allpet-install` 入口，npx 从 GitHub 获取并执行。安装器本身没有第三方 npm 依赖、安装生命周期脚本或后台定时任务。它不改变 `desktop/` 的 Electron 构建入口。

## 执行后会发生什么

| 阶段 / 操作 | 具体表现 |
| --- | --- |
| 运行命令 | 识别操作系统与硬件 CPU，查询 GitHub 最新正式版；不选择草稿或预发布版 |
| 架构检测 | 支持 macOS 14+ Apple Silicon、Windows x64、Linux x64；Mac 在 Rosetta 下运行 x64 Node 仍识别为 Apple Silicon。Intel Mac、Windows ARM、Linux ARM 暂不安装 |
| 已有相同或更高稳定版本 | 提示无需更新并退出；Mac 不重启当前程序，已有应用和设置不变 |
| 尚未安装 / 有更新 | 下载该系统的 ZIP / EXE / AppImage，显示进度；校验文件大小和 SHA-256，验证通过才安装 |
| 下载失败、限流、校验不符 | 显示原因及手动下载链接，返回非零退出码；不执行下载内容、不替换原应用 |
| macOS 安装 | 解包并核验包 ID、版本、严格签名；暂存旧包，退出目标位置的 AllPet，替换 `/Applications/AllPet.app` 后启动。替换失败尝试恢复旧包，成功后删除暂存旧包 |
| macOS 系统提示 | 如系统要求确认打开或辅助功能授权，在系统设置完成；安装器不移除隔离属性、不关闭 Gatekeeper、不自行授予权限。无法写入 `/Applications` 时停止，请按系统权限手动安装 |
| Windows 安装 | 运行 Release 中的官方 NSIS 安装器，沿用它的安装位置与系统提示；完成后从应用 ID 对应注册表项及可执行文件核实版本。用户取消不报告成功 |
| Windows 已有多个系统安装项 | 停止并提示先在“已安装的应用”中整理，避免随意选择和修改一份安装 |
| Linux 安装 | 将 AppImage 写入 `~/.local/opt/allpet/AllPet.AppImage` 并设置可执行，写入版本/校验记录和应用菜单入口；无需 sudo。由应用菜单打开；更新后需自行退出旧进程再打开 |
| Linux 应用菜单 | 创建 `${XDG_DATA_HOME:-~/.local/share}/applications/allpet.desktop`；绝对路径启动，处理空格与特殊字符。桌面环境可能需要刷新菜单 |
| 再次执行同一行命令 | 再查最新正式版，有更新就更新同一目标；没有更新就退出。不是后台自动更新 |

Linux AppImage 仍依赖桌面环境、FUSE 和 Electron 的系统运行条件。环境不支持时可使用 Release 中的 DEB。已经用 DEB/系统包管理器安装的用户应继续使用同一渠道；安装器不卸载系统包、不寻找或删除其它目录中的手工副本。Linux 遇到目标位置已有不属于本安装器的文件或文件校验不符，会停止而不是覆盖。

配置、宠物、任务历史保存在原应用数据目录，安装器不删除这些目录。它只管理上表的应用安装位置；npm 的下载缓存是安装工具缓存，不是额外运行的桌宠。

## 预览和帮助

仅查询版本、架构、下载文件和安装位置，不下载安装包、不修改应用：

```bash
npx --yes github:haverainlilili/all-pet --dry-run
```

查看参数：

```bash
npx --yes github:haverainlilili/all-pet --help
```

`--yes` 只省略 npm 对执行入口包的确认，不代表授予操作系统权限。首次运行 npx 仍需联网获取入口包。安装包的 SHA-256 优先使用 GitHub Release API 的资产摘要；旧资产没有摘要时读取该 Release 的 `SHA256SUMS`。它验证文件与发布记录一致，不代替 Apple 公证或 Windows 代码签名。

## 开发与验证

根目录 `npm test` 覆盖系统/架构拒绝、Rosetta、WSL、稳定版本比较、错误下载、完整性校验、替换回滚、Windows 注册表/进程退出与 Linux 更新/数据保留。

`.github/workflows/installer.yml` 在 macOS、Windows、Linux 上测试 npm 包入口，再下载安装当前正式 Release 到一次性 CI 机器。Mac 验证两次安装和签名；Windows 验证 NSIS 静默安装/复用路径/注册表版本后卸载；Linux 验证两次安装、AppImage 运行时和桌面文件格式。此脚本要求 GitHub Actions 环境，不在用户机器上执行安装验收。CI 的 Windows 静默模式是自动测试选项，公开命令默认使用安装器正常界面。

安装入口独立于桌宠版本：本次增加入口仍安装正式版 **v1.5.0**，不重写既有 Release 或发布标签。命令的 GitHub 包格式遵循 [npm package spec](https://docs.npmjs.com/cli/v11/using-npm/package-spec/)，单一 `bin` 入口由 [npm exec/npx](https://docs.npmjs.com/cli/v11/commands/npm-exec/) 选择。
