# AllPet 九平台接入与验收说明

v1.4.1 接入说明。功能限制与验收结果见 [平台行为验收](平台行为验收.md)。

记录日期：2026-09-26。对应 v1.4.1 源码；v1.4.0 安装包不含 Windows/Linux 持续菜单修复。完整功能与逐项点击反馈见 [功能设计说明](./功能设计说明.md)。

## 使用入口

菜单栏/托盘 → **气泡显示平台**，勾选允许展示的平台。支持 Codex、Claude Code、DSH、Grok、Cursor、WorkBuddy、Qoder、pi 和 Z Code；支持全部显示、全部隐藏，设置重启后保留。macOS 原生版及 Electron 原生菜单桥接中，点击平台勾选项、全部显示或全部隐藏后菜单保持展开，勾选立即更新，可连续操作；Windows/Linux 从 v1.4.1 起使用持续菜单面板，同样可连续设置。点击外部或按 Esc 关闭。

隐藏只过滤气泡，不停止日志扫描、不删除历史、不关闭原平台任务。重新显示时恢复未确认且未过期的通知；隐藏期间历史的 24 小时过期规则继续生效。宠物动画按允许展示的平台状态计算。平台列表每页 4 个，可点上一页/下一页；九个平台共 3 页。

所有平台的完成/失败通知均为**点击即确认**：先移除通知并保存，再尝试打开任务。定位失败或取消不会恢复已确认通知；新一轮 running/thinking/waiting 活动才撤销旧确认。活跃任务点击保留。点单条或整个平台的 × 只关闭通知，不终止任务。

Codex CLI 等终端工具的日志监控、点击定位与手动查看能力分别见 [终端 CLI 支持说明](终端CLI支持说明.md)。

## 新增平台

| 平台 | 默认来源 | 设置步骤 | 点击任务的定位能力 |
| --- | --- | --- | --- |
| Cursor | `~/.cursor/projects/**/agent-transcripts/` 的 JSONL/TXT | 点“实时状态接入 → 启用/修复 Cursor”，再开始新一轮任务；未生效时重启 Cursor | macOS 打开应用，用户自行选择会话 |
| WorkBuddy | `~/.workbuddy/projects/**/*.jsonl` | 无需 hook，开始新任务 | macOS 打开应用，用户自行选择会话 |
| Qoder | `~/.qoder/projects/**/*.jsonl` | 点“实时状态接入 → 启用/修复 Qoder”，重启 Qoder 再开始新一轮任务 | macOS 打开应用，用户自行选择会话 |
| pi coding agent | `~/.pi/agent/sessions/**/*.jsonl` | 无需 hook，在 pi 中开始新任务 | AppKit 尝试可验证的原终端；Electron 提示手动查看现有终端 |
| 智谱 Z Code | `~/.zcode/cli/db/db.sqlite` | 无需 hook，开始新任务 | macOS 打开 ZCode 应用，用户自行选择会话 |

Windows/Linux 的新增 GUI 平台在任务点击后说明限制，并提供“只打开平台”；依赖系统能发现对应应用命令。没有编造现有会话深链，也不会把“应用已打开”报告为“原会话已聚焦”。pi 任务点击不会启动重复进程；空平台的“打开平台”操作是独立入口。

非默认安装、远程主机或自定义数据目录不会自动推断。可在 `~/.config/all-pet/config.json` 中修改 `platforms.<key>.paths` 后重启 AllPet。隐藏平台用顶层 `hiddenBubblePlatforms`，例如 `["cursor", "pi"]`；停止该平台监控则是 `platforms.<key>.enabled=false`。原生平台自己的目录环境变量不保证自动映射到 AllPet。

## Cursor / Qoder 的观察 hook

原生日志不一定包含可靠的结束事件，因此接入 hook 后才能完整跟踪提示提交、工具活动、等待和明确停止。

| 平台 | 用户配置 | 安装事件 |
| --- | --- | --- |
| Cursor | `~/.cursor/hooks.json`，version 1 | beforeSubmitPrompt、preToolUse、postToolUse、stop |
| Qoder | `~/.qoder/settings.json` | UserPromptSubmit、PreToolUse、PostToolUse、PostToolUseFailure、PermissionRequest、Stop |

也可使用编译后二进制：`allpet integrations install cursor` 或 `allpet integrations install qoder`。安装过程保留原有 hooks 和其它键；修改现有配置前写同目录 `*.allpet-backup-<UUID>` 备份。相同程序路径重复安装不重复注册。无法读取、JSON 损坏或 hooks 结构不支持时失败，不覆盖原配置。

每个 hook 运行当前 AllPet 核心二进制的 `hook <platform>` 命令，超时 5 秒；输入最多 1 MiB，输出为空 JSON 对象，不作批准/拒绝决定。只在本地 `~/.config/all-pet/events/<platform>/` 保存会话 ID、工作目录、来源路径、工具名和阶段。文件名编码 ID，目录权限 0700、文件 0600；不写入提示词、工具参数、模型回复。

卸载接入：在平台配置中仅移除命令结尾为 `hook cursor` / `hook qoder` 且路径指向 AllPet 的条目，保留其它用户 hooks。需要完整回退时可从备份恢复，但应先核对备份之后用户是否又更改过配置。移动 AllPet 应用后，重新运行接入并移除旧路径条目；当前按完整命令去重，不自动删除旧安装位置的命令。

平台没有开始过新任务、日志超过最近活动窗口或日志尚未落盘时，状态可能为空闲。Cursor 未接 hook 时不会凭无新日志猜测“已完成”；hook 先到而标题日志未到时会暂时显示短 ID。明确的子代理/sidechain 不生成独立气泡。

## Z Code 数据库

读取 session/message/part/todo 的少量状态字段，按 task_type 过滤子代理和子工作流，保留用户 fork。数据库及 WAL 时间/大小共同决定缓存更新；不写入平台数据库。

Electron 包内带 `sqlite/sqlite-read.js`，使用自身 Node SQLite，无需额外安装 sqlite3。独立 macOS/Linux 核心可以使用 `/usr/bin/sqlite3` 或 `/opt/homebrew/bin/sqlite3`。也可配置 `ALLPET_SQLITE_EXECUTABLE` 和 `ALLPET_SQLITE_SCRIPT` 指向兼容的 Node/Electron 和该脚本；独立 Windows CLI 无默认 sqlite3 回退。结构发生不兼容变化时显示“无法读取 Z Code 会话数据库”，需按新版本更新适配。

## 实际验证与限制

- 本机 WorkBuddy 的本地日志形状已核对；只读取格式，未向平台提交测试任务。
- Cursor/Qoder 按官方 hooks/日志约定接入，pi/Z Code 对照官方源代码实现。隔离 HOME 的原生格式夹具验证了五个平台、标题/会话 ID、完成/等待/工具状态、子任务过滤、hook 合并与重复安装。
- Z Code 使用实际 SQLite/WAL 夹具验证只读查询与常驻 watch 缓存更新；该测试检查读取前后数据库和 WAL 内容不变。
- AppKit 与 Electron 测试覆盖九平台显示设置、历史保留与统一终态点击行为。详细最终数量和打包结果见功能设计文档第 12.4 节。
- 当前机器没有 Cursor、Qoder、pi、Z Code 的完整真实运行环境；未进行这四个平台真实任务的端到端验收，也未新增 Windows/Linux 实机验收。各产品后续更改私有本地格式可能需要维护适配。
- `sessions list/transcript` 是另一个开发中的导出功能，仍只解析原有四个平台；本次新增的是五平台实时监控和桌宠通知能力。

## 格式依据

- [Cursor Hooks 官方文档](https://cursor.com/docs/hooks)：事件名、用户 hooks 配置及观察接口。
- [Qoder Hooks 官方文档](https://docs.qoder.com/extensions/hooks)：配置、事件与会话记录格式；[Qoder Deep Link](https://docs.qoder.com/user-guide/deeplink) 未提供已核实的现有会话精确聚焦接口。
- [pi 会话格式](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/sessions.md) 与 [session-manager 源码](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/src/core/session-manager.ts)：会话 ID、树形消息条目和名称记录。
- [Z Code 官方源码](https://github.com/zai-org/ZCode) 的 SQLite session/message/part/todo 存储及 [Hooks 文档](https://zcode.z.ai/en/docs/hooks)。本实现使用只读数据库，不安装 Z Code hooks。
- WorkBuddy 依据本机 `/Applications/WorkBuddy.app` 及 `.workbuddy/projects` 原生日志形状核对；尚无本实现依赖的稳定公开会话深链。

## Codex 手动查看完成任务

macOS Electron 版每 0.5 秒独立检测已完成的 Codex 任务，不依赖新增日志。用户在 Codex 中手动进入原任务后，前台主内容标题与唯一会话匹配时清除对应气泡并持久记为已确认；这条标题路径需要辅助功能权限。观察到 Codex 本地同账号、同主机的“未读→已读”变化也可精确清除，不需要辅助功能权限。启动时没有未读标记不代表已读；旧气泡依靠前台标题检查。标题重复/不可读、权限缺失且没有已读变化时保留通知，可点击气泡或 × 确认。

隐藏平台、运行中/等待中/失败任务不参与这条 done 检测。每次异步确认核对原完成轮次，防止误删新的任务。Claude、DSH、Grok、pi 的 macOS 检测通道已补接，前台、会话、终端绑定条件和未完成事项见 [平台行为验收](平台行为验收.md)。Windows/Linux 不因此具备同等检测能力；九平台的点击完成/失败气泡即确认规则仍一致。

若手动进入旧任务仍不清除，请检查 AllPet 菜单的“Codex 自动确认”权限状态。点击“开启辅助功能权限…”可打开系统设置，由用户确认授权 AllPet；测试进程有权限不代表常驻应用也有权限。没有授权且任务早已是已读状态时，不能保证自动清除。已授权且前台唯一标题可读时，按通常 2 秒内清除验收。
